# Synthesis: trace-based testing prior art (2026-11-08)

Inputs: `00-brief.md`, `01-research/prior-art/*.md` (6 tools), three opinion files. Comparables rows 7-8 (Helios trace-to-test, Hurl/Venom) were held in reserve and not researched in depth. Evidence labels are carried over from the source files unchanged. **Docs** means what a tool does. **Opinion** means what users say. INFERENCE marks reasoning that has no source behind it.

## 1. Implementation patterns (by mechanism)

**P1. Post-hoc selector + assertion list.** The tool gets the trace after the run finishes, either by receiving OTLP itself or by polling a backend. It then selects spans with a query and checks each matched span against assertions. Users: Tracetest (`span[attr op "value"]` + `attr:x op v`, YAML, web UI builds a selector from a picked span), and TraceQL as a query grammar. Docs: Tracetest has "outputs" for chaining tests, which matches the brief's "wire up inputs and outputs".

**P2. In-process code assertions on captured spans.** An in-memory exporter or span recorder holds the spans. Test code queries them and asserts with the host test framework. Users: Malabi (JS; archived 2024-10-31) and Go OTel `sdk/trace/tracetest` (capture only, no assertion layer). The test is plain code, and each test gets its own trace scope through a callback.

**P3. Record-and-generate / golden.** The tool records a session and emits editable code. The user either picks assertions from the recording or the tool stores the whole output and diffs against it later. Users: Playwright codegen (UI assert-mode, aria snapshots), Cypress Studio (incl. cloud-gated AI suggestions), Jest inline snapshots, goldie, cupaloy, teatest, VHS, and praytel's own golden trace trees. Trace-to-test generators Kolo (`generate-test`, alpha) and Helios are UNVERIFIED.

**P4. Periodic query-and-alert over stored traces.** A saved query runs on a schedule or window against a trace store and fires when it crosses a threshold. Users: Honeycomb triggers (scalar result, 1-1440 min frequency) and Grafana TraceQL alert rules (private preview, not for production). Docs: neither is streaming. Neither turns a violation into a test.

**P5. Generative property / invariant checking.** The tool generates inputs and drives deterministic code. An invariant runs after every step. A failure is shrunk and saved as a replayable example. Users: Hypothesis (`@invariant`, example DB as a cache, `@example` for durable pins), rapid (Go). Docs: neither watches an external live process. How this would apply to live traces is INFERENCE only.

**Cross-cutting substrate: Starlark (mandated).** Starlark is not a pattern. It is the logic layer that any of P1-P5 would sit on in praytel. Docs (STRONG) show it is deterministic, the host controls every builtin, it has a deterministic step cap and goroutine-safe `Cancel`, and errors carry file:line:col positions.

## 3. Recurring failure modes

1. **Trace completeness and arrival timing.** This shows up in Tracetest polling (late spans missed: ANECDOTE; a multi-root bug, maintainer-confirmed, likely STALE), in batch-processor flush flakes (ANECDOTE), and in teatest's timing-based `WaitFor` (docs). Praytel still has to decide when a run's trace is "done", for example for spans flushed at or after child exit.
2. **Sampling drops the trace under test** (MODERATE, two or more guides). Applies to any app that tail-samples before exporting to praytel.
3. **Brittleness to names and volatile values.** Span renames break assertions (MODERATE). Generated or golden tests pin timestamps, UUIDs and hosts (Jest, cupaloy docs; Sorbet; vendors). Mitigations that recur across sources: attribute-based selectors, normalizing volatile values in one central place, and partial matching.
4. **Unreviewed regeneration** blesses bugs (Jest docs; vendors MODERATE; Sorbet dissent below).
5. **Expression-language runtime errors on absent data.** CEL "no such key" errors and the need for `has()` guards on optional fields (MODERATE-to-ANECDOTE). This maps directly to asserting on optional span attributes.
6. **DSL expressiveness ceiling.** Tracetest's precedence bug and events MVP (STRONG, docs).
7. **Runaway or undebuggable config programs** (ANECDOTE forum). Starlark's step cap and `Cancel` address CPU use. Memory and long-running builtins stay unbounded (STRONG).
8. **Project abandonment.** Malabi is archived (STRONG, repo). Tracetest status is unclear (below).

## 4. Surprises and dissent

- **Tracetest status conflicts.** The kubeshop org page reportedly lists it as archived or not maintained (UNVERIFIED, search summary). The repo shows no banner. The last release found is v1.7.1, 2024-10-10. Discontinuation of Cloud/Enterprise is reported via stackpick only (ANECDOTE/MODERATE, primary announcement not read). `tracetest run` is not in the official docs page that was read (ANECDOTE source).
- **Brittleness dissent.** The Sorbet maintainer accepts exact-match brittleness when updates are mechanical and reviewed. Vendors call the same thing noise. Both agree on normalization.
- **Code vs data.** One (biased) author argues generated tests should be stored as data, not code. That runs against the brief's mandate for code test files. CircleCI argues a full DSL brings debugging complications (ANECDOTE). Earthly and Tilt argue for real control flow (MODERATE, vendor-biased).
- **Starlark looks like Python but has no exceptions.** A failing assertion kills the thread, so a script cannot catch a failure and continue (docs, STRONG). Whether multiple failures can be collected was not tested.
- **Starlark is not a security sandbox** (README, STRONG). It has no tagged releases, only pseudo-versions, and the project reserves the right to break the API. The step unit may change between versions.
- **Grafana's own guidance** steers alerting away from trace queries toward span metrics (STRONG). The vendor closest to "trace properties" does not endorse doing it live on traces.
- The Go OTel package is also called `tracetest`, the same name as the Tracetest product.
