## Option B: Subcommand registry, typed usage errors, event-driven Reporter   (stance: most extensible)
Summary: `runProcess` looks up `argv[0]` in a subcommand registry before falling back to today's `args.Parse`. `test` is the only entry. A separate runner package turns cases into outcome events and sends them to a `Reporter` interface. v1 ships one streaming text reporter and no new flags, so the v1 surface matches the vision exactly.

How it works:
- `cmd/praytel/main.go:63-75`: `if sub, ok := registry[argv[0]]; ok { return sub.Run(ctx, argv[1:], io) }`. Otherwise the root path is unchanged. A pre-check sees a registered name before `--` in a root argv and adds `praytel: put flags after "test"` above the usage line.
- New `cmd/praytel/internal/usage`: `type Error struct{Msg string}` prints `praytel: <msg>`. `newErrMapper` (`main.go:46-49`) gains an `errors.As` branch that returns exit 1. `ErrUsage` stays as it is.
- New `cmd/praytel/internal/testargs`: its own `flag.FlagSet`, with `Mode` ∈ {Files, Record}. `Watch` is a reserved enum value that is not parsed in v1. It reuses the root defaults through named consts (today these are literals at `args.go:107-108`). It rejects `--tui`/`--snapshot`, `--` with files, and files with `--record`.
- New `internal/testrun`:
  - `Expand(args, fs.FS) ([]string, error)`: pure function, S3 rules.
  - `Run(ctx, files, Executor, Reporter) Outcome`: calls `praytest.Load` for every file first and aggregates `UsageError`s (D5). Then, per case, it calls `Executor` (a func that `cmd/praytel` backs with D2's `runCase`), then `Case.Check` (D6), then the D2 step-6 classifier.
  - `Reporter{FileStart(path, n); Case(CaseReport); NotRun(name); Summary(Totals)}`. `CaseReport` = `{File, Name, Outcome, Failures []praytest.Failure, Note, Captured}`.
  - `textReporter` streams the S2/S3 format per case.
  - The exit code is folded in `Run` (worst result), not in the reporter, so a reporter cannot change the verdict.
- Later additions, not built now: `--format=json|junit|github` reporters, `praytel <sub>` entries, and a v1.1 `WatchReporter{Violation; Wrote}` for S6's alert lines.

Steelman: Every argv whose first token is not a flag or `--` is a usage error today. `args.Parse` stops at the first non-flag and `NArg != 0` returns `ErrUsage` (`args.go:118-124`). So the registry claims a namespace that no working invocation uses, and the same holds for any future name (R10). Putting events behind a Reporter is the step that makes golden reports testable without a child process. CI annotations and JUnit are the obvious next asks for a required check (R7). Adding them later then means one new type, with no runner change.

Pros: each piece can be tested on its own (fake Executor, fake events, an `Expand` table for M8). `main` stays thin. There are no dependencies. Watch and future subcommands plug in without touching the root parser.

Cons / failure modes / hidden costs:
- A registry with one entry and an interface with one implementation are speculative (R8).
- The event shape is guessed before a second consumer exists. JUnit wants durations and per-file grouping that `CaseReport` may lack, so v1.1 could still reshape the interface.
- Four places produce usage wording: dispatcher, `testargs`, `Expand` and `Load`.
- Because `runCase` lives in `package main` (D2), `Executor` is an injected seam.
- New exported functions each need spans (`CONTRIBUTING.md:16-45`).
- The hint pre-check is the only new code on the root path, and it changes stderr for an argv that already fails.

Criteria scores:
- Backward compatibility: 5. The namespace is free (`args.go:122-124`), and the root path is untouched apart from a hint on an argv that already errors.
- Precise usage errors: 4. A typed error and load-all-before-run, but the wording is spread over four sites.
- Testability: 5. Report goldens come from synthetic events, and the M8 and M4 tables run on `Expand` alone.
- Package boundaries: 4. `main` is thin, but there are three new packages and an injected executor.
- Extensible: 5. `--watch`, new reporters and subcommands are all additive.
- No new deps / stdlib `flag`: 5. Stdlib `flag` only.

Cost: M     Reversibility: easy (all internal; the public surface is the vision's)

Unknowns / assumptions:
- That a `Reporter` event shape fits S6's watch stream. Watch writes during the run and has no per-case verdict, so it may need its own interface.
- That moving the drain defaults to named consts counts as not changing root parsing.
