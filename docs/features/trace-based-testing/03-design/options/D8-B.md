## Option B: Fprintf generator, keyword refusal, self-load check, link-based no-clobber write   (stance: minimal change)
Summary: A single Go function prints the S1 shape with `fmt.Fprintf` into a `bytes.Buffer`. A few quoting helpers emit typed literals, and selectors come from D7's `Selector.Source()`. Before writing, the bytes are loaded in-process and run against the recorded view. The file is published with a temp file plus `os.Link`, not `rename`, because `rename` overwrites.

How it works:
- **New file:** `internal/praytest/gen.go`. It goes there because quoting must match the pinned interpreter, and D4 allows only this package to import it.
- **Entry point:** `Generate(r Recording) ([]byte, error)`.
- **`Recording` type:** `{File string; Argv []string; Running bool; Cases []GenCase}`.
- **`GenCase` type:** `{Name string; Sel selector.Selector; Asserts []Assert{Field, Value domain.Value}; Absent []selector.Selector}`.
- **Ordering:** picks are sorted by (span box, field) before printing.
- **Names:**
  - A constant name is the upper-snake form of the last segment of the span name (`CHARGE`). A collision gets `_2`.
  - The case name and `check_<name>` come from the file basename. If the basename is not a valid identifier, the write is refused.
- **Literals:**
  - Strings use `starlark.String(s).String()`.
  - Ints use `strconv.FormatInt`.
  - Floats use `FormatFloat('g',-1)`, with `.0` added when the result has no `.` or exponent. NaN and Inf are refused.
  - Status is one of `"unset"`/`"ok"`/`"error"`.
  - Array, map and bytes values are refused, per D7.
- **Header:**
  - Line 1: `# praytel test format v0. Recorded with: ...`.
  - The argv is shell-quoted in the comment. Any `\n` becomes `\\n`, so an argument cannot end the comment.
  - The WARNING line is printed iff `r.Running`.
- **Volatile guard:**
  - There is no field for ID, time or duration in `Recording`, so these values cannot reach the output by construction.
  - Attribute picks are refused when the key matches the denylist `*port`, `*.time*`, `*_unix_nano`, `trace_id`, `span_id`.
  - Picks are also refused when the value matches one of: 32 or 16 hex characters, RFC 3339, or `host:port`. The refusal message names the key (`card.type` passes).
- **Self-check:**
  - `LoadFile` runs on the generated bytes. It must register exactly 1 case whose argv equals `r.Argv`.
  - The case's `check` then runs against the current `CheckView`. Any failure refuses the write and shows the reason in the status line.
- **Write:**
  1. `os.CreateTemp(dir(File), ".praytel-*")`, write, `fsync`.
  2. `os.Link(tmp, File)`, which fails with EEXIST if `File` already exists.
  3. Remove the temp file.
  4. If `Link` returns EPERM or ENOTSUP (FAT, some network filesystems), fall back to `O_CREATE|O_EXCL` + write + `fsync`, and remove `File` on a write error.
- **Golden test:** `testdata/gen/*.golden`. The M3 test generates a file for every `shop` span.
- **v1.1:** watch calls `Generate` with its own `Recording`, with no TUI involved.

Steelman: About 200 lines, with no template engine and no AST. Quoting is done by the interpreter that later reads the file, so round-trip is exact by construction. The two acceptance claims, "parses" and "passes", are checked against the real loader and the real run before any byte reaches disk. So "guaranteed or refused" is literally true for the recorded run. `Link` gives no-overwrite and no-partial-file in one syscall on every common local filesystem.

Pros:
- Byte-stable output, golden-testable, and readable output identical to S1.
- Refusals carry a reason.
- No new dependency.

Cons / failure modes / hidden costs:
- **Attribute volatility is a heuristic.** A volatile value such as a temp path `/tmp/x123`, a PID or a business ID can pass the denylist. M3 holds only for `shop`'s keys.
- **Self-check scope.** It proves the file passes on *this* run, not on a rerun. A value that differs between runs but is not on the denylist still produces a flaky file.
- **Fprintf structure.** The structure is spread across format strings, so adding repro predicates (lambda bodies, `load()`) means growing ad-hoc branches. `Recording` has no slot for a predicate, so v1.1 must extend it.
- **Link fallback.** The fallback path can leave a partial file if the process crashes mid-write.
- **Collision order.** The `_2` suffixes depend on sort order, which is stable but arbitrary.

Criteria scores:
- Zero volatile values (25): 3. IDs, timestamps and durations are excluded structurally. Attribute values are only filtered by a heuristic.
- Passes on unchanged command (20): 4. The in-process check against the recorded view proves it for one run. Cross-run variance is not covered.
- Readable/idiomatic (20): 5. The output matches the S1 text exactly.
- Safe write (15): 4. `Link` is atomic and no-clobber. The rare fallback path is not.
- Byte-stable (10): 5. Inputs are sorted and the output is pure bytes, so golden files work.
- Reusable for repros (10): 3. Callable without a TUI, but predicates need a new field and printing branches.

Cost: S     Reversibility: easy (internal code). Only the v0 header text is public.

Unknowns / assumptions:
- That `starlark.String.String()` output always re-parses (believed true, not verified).
- That `CheckView` is available at Ctrl-W in a form the check can run on (depends on D9 and D6).
- That a denylist is acceptable as the meaning of M3's "ports".
