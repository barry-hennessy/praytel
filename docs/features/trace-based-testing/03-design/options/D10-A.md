## Option A: One branch in `runProcess`, the whole runner in `cmd/praytel/test.go`   (stance: minimal change)
Summary: `runProcess` checks `argv[0] == "test"` before `args.Parse` and hands off to `runTest`. Parsing, input expansion, the loop over cases, the report and the worst-exit fold all go in one new file in `package main`, next to `run.go`. `internal/args` stays as it is.

How it works:
- `main.go:63`: add `if len(argv) > 0 && argv[0] == "test" { return runTest(ctx, lt, mapErr, argv[1:], os.LookupEnv, stdout, stderr) }`. `newErrMapper` (`main.go:36-57`) gets one more branch. A `usageErr string` prints `praytel: <msg>` and returns 1. On `args.ErrUsage`, if `"test"` occurs before the first `--`, it first prints `praytel: put flags after "test"`.
- New `cmd/praytel/test.go`:
  - `parseTest(argv, errOut) (testConfig, error)` splits at `slices.Index(argv, "--")` and uses its own `flag.NewFlagSet("praytel test")` with `--record`, `--grpc-port`, `--http-port`, `--drain-idle` and `--drain-timeout`, with the same defaults as `args.go:105-108`. `--tui` and `--snapshot` are registered only so they can be rejected precisely. `testConfig{Files []string; Record string; Cfg args.Config}`. The record-mode and file-mode conflict rules are plain `if`s. `--watch` will be one more flag and one more rule set.
  - `expandInputs([]string) ([]string, error)` handles the S3 rules with `os.Stat`, `filepath.Glob`, `filepath.WalkDir` (skips dot-dirs and symlinked dirs) and dedupe by `filepath.Abs`.
  - `runTest` runs expand, then `praytest.Load` on every file and gathers every `UsageError` (D5). If there are any, it prints them and returns 1. Otherwise, for each file and case, it calls `runCase(..., caseOpts{Isolate: true, Deadline: c.Timeout, View: settle})` (D2), then `classify` (D2 step 6), then `Case.Check` (D6). It streams the header, the `ok/FAIL/INCOMPLETE` line and the `Failure.Lines()` to stdout as it goes. Captured output goes to stderr on an exit mismatch. A running `worst` (interrupted 130/143 > 4 > 3 > 0) becomes the code returned with the summary line.
- Rollout: lands after D2's `runCase` extraction PR. Root parsing is unchanged.

Steelman: Today every argv whose first word is `test` is already a usage error. Without `--`, `args.go:91-92` rejects it. With `--`, `"test"` is a stray positional and `args.go:122-124` rejects it. So the branch cannot change any existing successful invocation, and `praytel -- test` still reaches `/usr/bin/test`. This option adds no package, interface or dependency. The code sits next to `runCase` and `startChild`, which it calls directly. `runProcess` already takes injected writers (`main.go:63`), so tests can run the report in-process.

Pros: the smallest diff; cannot regress the root path; stdlib `flag` only; easy to read in one file.

Cons / failure modes / hidden costs:
- `package main` gains about 400 lines of logic: the parser, expansion, classifier and report. D8, D9 and D12 cannot import any of it, so watch alerts and Ctrl-W have to copy the report and verdict text or move it out later.
- `flag` stops at the first positional, so `praytel test a.praytest.star --grpc-port=0` fails as a missing file named `--grpc-port=0` instead of giving a flag hint.
- `flag`'s own messages (`flag provided but not defined: -x`) need wrapping to get the `praytel:` prefix.
- Each future subcommand adds another `argv[0]` branch plus an ErrMapper case.
- The M8 and golden tests live in `cmd/praytel`. Every function there must carry spans (`CONTRIBUTING.md:42-44`), which adds trace-golden churn.
- The hint is a heuristic. It also fires for `praytel --tui test -- cmd`, which is also a usage error.

Criteria scores:
- Backward compatibility: 5 - only argvs that are rejected today are affected (`args.go:91-97,122-124`).
- Precise usage errors: 4 - all exit 1 before `runCase`, but flags placed after file arguments get a misleading message.
- Testability: 4 - in-process through `runProcess` and `expandInputs`. Case runs still spawn real children.
- Clear package boundaries: 2 - the logic is in `cmd`, not `internal`.
- Extensible to `--watch`/subcommands: 3 - fine for `--watch`, an if-chain for more.
- No new CLI deps: 5 - stdlib `flag` only.

Cost: S     Reversibility: easy (everything is unexported in `main`, so moving it to `internal` later is mechanical)

Unknowns / assumptions:
- D2's `caseResult` exposes the captured child stdout/stderr for the mismatch dump.
- Exit 130/143 for an interrupted run is still waiting for human confirmation. If it is rejected, the fold uses the fallback 3.
- D9 owns what `--record` does after parsing.
